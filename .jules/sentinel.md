## 2025-05-15 - [HIGH] Path Traversal in API Endpoints
**Vulnerability:** The endpoints `/api/v1/run`, `/api/v1/search/setup`, and `/api/v1/gems/refine` allowed users to provide arbitrary strings for `search_id`, `gem_id`, and `local_dir`. These strings were used to construct file paths (e.g., `os.path.join("runs", search_id)`), enabling an attacker to read or write files outside the intended directories using `..` sequences or absolute paths.
**Learning:** File system operations that depend on user-provided identifiers are highly susceptible to path traversal if the identifiers are not strictly validated against a whitelist pattern. Relying on `os.path.join` alone is insufficient as it does not prevent parent directory navigation.
**Prevention:** Enforce strict validation on all ID-like fields using a whitelist regex (e.g., `^[a-zA-Z0-9_-]+$`) and explicitly reject absolute paths or paths containing `..` in directory fields using Pydantic `field_validator` decorators.
