## 2026-07-31 - Path Traversal in API Endpoint Identifier Routing
**Vulnerability:** User-controlled input fields `search_id`, `candidate_id`, `gem_id`, and `local_dir` were passed directly into file and directory path construction operations (such as `os.path.join` and f-strings targeting prompt files) without prior sanitization or regex filtering. A malicious user could exploit this to perform path traversal (`../`) to read or write arbitrary files on the system or access unauthorized directories.
**Learning:** In highly modular or pipeline-driven applications, API request payloads are often directly mapped to local file structures to keep track of runs, candidates, and configuration templates. Relying on lower-level file libraries (like `os.path.join` or custom input loaders) to securely handle arbitrary strings introduces security gaps if Pydantic input models do not strictly constrain string contents.
**Prevention:** Always enforce strong schema validation directly at the boundary of incoming requests. Use Pydantic's `@field_validator` with strict whitelist patterns (e.g., `^[a-zA-Z0-9_-]+$`) for IDs and block directory traversal sequences (like `..`) and root/absolute path constructs for relative paths.
