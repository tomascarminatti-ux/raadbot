## 2025-05-18 - Pydantic Field Validation for SSRF and Path Traversal Prevention
**Vulnerability:** API endpoints (`/api/v1/run`, `/api/v1/search/setup`, `/api/v1/gems/refine`) accepted unvalidated string parameters (`search_id`, `candidate_id`, `gem_id`, `local_dir`, `webhook_url`). Attackers could pass directory traversal vectors (e.g. `../`) or private IP/loopback webhook targets to trigger SSRF or arbitrary file access.
**Learning:** Pydantic models require explicit `field_validator` decorators to restrict identifier formats with strict regex (`re.fullmatch(r"[a-zA-Z0-9_-]+", v)`), block directory traversal sequences in file paths, and parse/validate IP addresses (`ipaddress.ip_address`) to block loopback, link-local, and private IP ranges for webhook URLs. In Pydantic field validators, `ipaddress.ip_address` checking must be isolated from custom `ValueError` exceptions so custom validation messages are not caught and suppressed.
**Prevention:** Always add Pydantic `field_validator` constraints on any request schema that accepts file paths, resource identifiers, or external URLs.
