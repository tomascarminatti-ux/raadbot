## 2026-04-20 - Input Validation, Path Traversal, and SSRF Hardening in API Models
**Vulnerability:** API endpoints (`/api/v1/run`, `/api/v1/search/setup`, `/api/v1/gems/refine`) accepted unvalidated string parameters (`search_id`, `candidate_id`, `local_dir`, `webhook_url`, `gem_id`). This allowed path traversal via `search_id` or `gem_id` (used directly in `os.path.join("runs", search_id, ...)` or `prompts/{gem_id}.md`), directory traversal in `local_dir`, and blind Server-Side Request Forgery (SSRF) / internal scanning via unvalidated `webhook_url` calls.
**Learning:** Pydantic models with only type annotations (like `str`) do not restrict characters or filesystem-sensitive sequences (`..`, `/`, `\`). When these values are later concatenated or passed to HTTP clients, path traversal and SSRF vulnerabilities occur if input sanitization is omitted at the schema level.
**Prevention:** Apply Pydantic `@field_validator` on all input models: validate identifiers with strict regex (`^[a-zA-Z0-9_-]+$`), inspect file/dir paths against traversal tokens (`..`) and absolute path roots, and restrict webhook URLs to `http`/`https` while barring localhost, private (RFC 1918), loopback, and link-local IP addresses.
