## 2026-08-05 - Path Traversal Vulnerability in API Request Schemas
**Vulnerability:** The application was vulnerable to path traversal (CWE-22) via `search_id`, `candidate_id`, `local_dir`, and `gem_id` parameters in API endpoints (`/api/v1/run`, `/api/v1/search/setup`, and `/api/v1/gems/refine`). Unsanitized inputs were used to dynamically construct filesystem paths for reading, writing, and creating directories, potentially allowing attackers to read, write, or overwrite files outside the intended directories (e.g. overwriting `README.md` or other system/source files).
**Learning:** Pydantic models by default accept any string value without restriction. When those string values are used directly in file system operations like `os.path.join` or `open()`, they can contain path traversal sequences (like `..`) or absolute paths, leading to Directory Traversal.
**Prevention:** Implement strict validation of all input parameters using Pydantic's `@field_validator` decorator. Restrict IDs to a safe alphanumeric/hyphen/underscore pattern and ensure path parameters are normalized, free of traversal patterns (`..`), and verified as relative.
