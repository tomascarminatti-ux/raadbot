## 2026-02-25 - Path Traversal and Identifier Hardening in API
**Vulnerability:** API endpoints (`/api/v1/run`, `/api/v1/search/setup`, `/api/v1/gems/refine`) accepted unvalidated string inputs (`search_id`, `candidate_id`, `local_dir`, `gem_id`) used directly in filesystem operations (`os.path.join`, reading/writing prompt files). This allowed path traversal (`../`) and arbitrary prompt file tampering.
**Learning:** Using raw string parameters in filesystem operations without strict Pydantic pattern validation and traversal checks enables directory traversal attacks. Furthermore, unconstrained identifier parameters in file modification endpoints like `/api/v1/gems/refine` allow arbitrary file writing outside the intended set of GEM prompt files.
**Prevention:** Enforce strict alphanumeric regex patterns (`r"^[a-zA-Z0-9_-]+$"`) on all user-supplied identifiers, implement explicit path traversal checks for relative directory paths (`local_dir`), and whitelist allowed GEM identifiers (`r"^(gem1|gem2|gem3|gem4|gem5)$"`).
