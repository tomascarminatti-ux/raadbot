## 2026-03-28 - Regex Fullmatch and Path Traversal Prevention in API Inputs
**Vulnerability:** API endpoints (`/api/v1/run`, `/api/v1/search/setup`, `/api/v1/gems/refine`) accepted unvalidated string inputs for `search_id`, `candidate_id`, `gem_id`, and `local_dir`. An attacker could inject path traversal sequences (such as `../` or `gem1/../../secret`) to write or read arbitrary files on the system or execute traversal file lookups.
**Learning:** `re.match` with `$` allows trailing newline characters (`\n`) in input strings. Using `re.fullmatch(r"[a-zA-Z0-9_-]+", v)` guarantees strict character-set enforcement. Additionally, normalizing backslashes (`\`) to forward slashes (`/`) before checking path traversal sequences (`..`) ensures robust cross-platform validation against directory traversal attacks.
**Prevention:** Always sanitize and strictly validate user-supplied file identifiers and directory path strings in request models using Pydantic `field_validator` with `re.fullmatch` and explicit path component inspection before passing them to filesystem operations (`os.path.join`, `open`).
