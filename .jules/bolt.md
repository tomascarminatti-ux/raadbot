## 2025-05-15 - [Prompt Construction & State Management Optimization]
**Learning:** In-place template building with multiple `.replace()` calls is a hidden bottleneck in high-throughput pipelines. Using `re.sub` with a replacement function provides a ~4x speedup. However, single-pass replacement fails when the base template itself contains placeholders. A two-stage approach (Base Template -> Rest of Variables) is necessary for correctness. Also, `@lru_cache` on instance methods is an anti-pattern as it binds to `self`, providing no benefit for one-off initializations and risking memory leaks.
**Action:** Always prefer module-level functions for file loading with caching. When optimizing string replacements, ensure the order of operations respects template inheritance (recursive-style).
