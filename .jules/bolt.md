## 2026-03-04 - Caching Disk I/O for Static Prompt Templates
**Learning:** Repeated synchronous file reading of static Markdown prompt templates (like `00_prompt_maestro.md` and agent instructions) causes a silent and significant disk I/O bottleneck in an ASGI (FastAPI) application. Decorating `load_prompt` with `@functools.lru_cache(maxsize=32)` yields a ~4.6x speedup on prompt building and reduces disk I/O completely. Proper cache invalidation is required when templates can be updated programmatically (e.g., via the `/api/v1/gems/refine` endpoint).
**Action:** Apply `functools.lru_cache` to any static asset loader functions, and ensure there is an explicit invalidation mechanism (like `.cache_clear()`) exposed and triggered in administrative/modification API endpoints.
